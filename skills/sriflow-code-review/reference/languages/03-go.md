# Go Code Review Guide

## Error Handling

### Ignored Errors — CRITICAL

Never ignore errors. Always check and handle.

```go
// CRITICAL — error silently ignored
file, _ := os.Open("data.txt")

// GOOD
file, err := os.Open("data.txt")
if err != nil {
    return fmt.Errorf("open data.txt: %w", err)
}
defer file.Close()
```

### Error Wrapping — MEDIUM

Wrap errors with `%w` for context. Use `errors.Is` and `errors.As` for comparison.

```go
// GOOD — wrapped with context
if err != nil {
    return fmt.Errorf("fetch user %d: %w", id, err)
}

// GOOD — checking
if errors.Is(err, sql.ErrNoRows) {
    return ErrNotFound
}

var apiErr *APIError
if errors.As(err, &apiErr) {
    log.Printf("API error: %s", apiErr.Message)
}
```

### Sentinel Errors — LOW

Define sentinel errors as package-level vars. Use `errors.New`.

```go
var ErrNotFound = errors.New("not found")

// GOOD
if errors.Is(err, ErrNotFound) {
    return nil
}
```

## Goroutine Patterns

### Goroutine Leaks — CRITICAL

Goroutines that block forever leak memory. Always provide an exit path.

```go
// CRITICAL — leaks if channel is never written to
func worker(ch chan int) {
    for val := range ch {
        process(val)
    }
}

// GOOD — with context cancellation
func worker(ctx context.Context, ch chan int) {
    for {
        select {
        case <-ctx.Done():
            return
        case val, ok := <-ch:
            if !ok {
                return
            }
            process(val)
        }
    }
}
```

### WaitGroup — MEDIUM

Use `sync.WaitGroup` when you need to wait for goroutines to finish.

```go
var wg sync.WaitGroup
for _, item := range items {
    wg.Add(1)
    go func(item Item) {
        defer wg.Done()
        process(item)
    }(item)
}
wg.Wait()
```

### Channel Rules — MEDIUM

- Only one goroutine should write to a channel.
- Buffered channels need explicit size justification.
- Don't pass channels in structs (prefer function params).

## Context

### First Parameter — HIGH

Context should always be the first parameter, named `ctx`.

```go
// GOOD
func GetUser(ctx context.Context, id int) (*User, error) {
    return db.QueryContext(ctx, "SELECT ...")
}

// BAD
func GetUser(id int, ctx context.Context) (*User, error) {
    ...
}
```

### Defer Cancel — HIGH

Always defer `cancel()` after `WithCancel`, `WithTimeout`, or `WithDeadline`.

```go
// GOOD
ctx, cancel := context.WithTimeout(ctx, 5*time.Second)
defer cancel()
```

## Interface Design

### Accept Interfaces, Return Structs — MEDIUM

This makes functions flexible for callers while keeping return types concrete.

```go
// GOOD
func Process(r io.Reader) (Result, error) {
    data, err := io.ReadAll(r)
    ...
}

// BAD — caller must pass concrete type
func Process(data []byte) Result {
    ...
}
```

### Small Interfaces — LOW

Prefer 1-3 method interfaces. The `io.Reader`, `io.Writer`, `fmt.Stringer` pattern.

## Receiver Types

### Pointer vs Value — MEDIUM

- Pointer receiver: modifies the receiver, large structs, implements interface.
- Value receiver: small structs (≤4 fields), no mutation needed.

```go
// GOOD — pointer receiver for mutation
func (u *User) SetName(name string) {
    u.Name = name
}

// GOOD — value receiver for read-only small struct
func (p Point) Distance() float64 {
    return math.Sqrt(p.X*p.X + p.Y*p.Y)
}
```

## Common Pitfalls

### Nil vs Empty Slice — MEDIUM

`nil` and empty slices are different but behave the same in most contexts. Be consistent.

```go
// nil slice
var s []int // s == nil, len(s) == 0, cap(s) == 0

// empty slice
s := []int{} // s != nil, len(s) == 0, cap(s) == 0

// For JSON: nil → null, empty → []
// Use empty for JSON APIs, nil for internal logic.
```

### Uninitialized Map — CRITICAL

Writing to a nil map panics. Always use `make`.

```go
// CRITICAL — panics
var m map[string]int
m["key"] = 1 // panic: assignment to entry in nil map

// GOOD
m := make(map[string]int)
m["key"] = 1
```

### Defer in Loops — MEDIUM

`defer` executes at function return, not loop iteration. Use anonymous functions.

```go
// BAD — all files closed at function return
for _, name := range files {
    f, _ := os.Open(name)
    defer f.Close() // all deferred until function exits
}

// GOOD — scoped per iteration
for _, name := range files {
    func() {
        f, err := os.Open(name)
        if err != nil {
            return
        }
        defer f.Close()
        process(f)
    }()
}
```

### String/Byte Conversion — LOW

Converting `string` ↔ `[]byte` copies data. For hot paths, use `unsafe` or avoid conversion.

## Common Mistakes Checklist

| Mistake | Severity | Fix |
|---------|----------|-----|
| Ignored error | CRITICAL | Always check err |
| Goroutine leak | CRITICAL | Use context, provide exit |
| Writing to nil map | CRITICAL | Use `make` |
| Missing defer cancel | HIGH | Always defer cancel |
| Wrong context as first param | HIGH | ctx is always param 1 |
| Defer in loop | MEDIUM | Wrap in anonymous func |
| Nil pointer dereference | HIGH | Check before use |
| Race condition on shared state | CRITICAL | Use mutex or channels |
